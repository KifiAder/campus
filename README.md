# Биржа проектов

Учебный веб-портал колледжа: студент регистрируется, публикует идею проекта и собирает
команду. Куратор видит все проекты и может менять их статус.

Стек: **HTML + CSS + JavaScript** (фронтенд), **Python** (сервер без фреймворков),
**MySQL / MariaDB** (база данных). При создании использовалась MariaDB

---

## Что умеет

| Возможность | Где смотреть |
|---|---|
| Регистрация: логин, имя, e-mail, пароль (хеш PBKDF2) | `/register` |
| Вход и выход, сессия в cookie | `/login`, шапка сайта |
| Публикация проекта: заголовок, короткое описание, подробное описание, теги | `/cabinet` → «Новый проект» |
| Список своих проектов с поиском | `/cabinet` → «Мои проекты» |
| Заявки (отклики) на мои проекты | `/cabinet` → «Входящие заявки» |
| Мои отклики на чужие проекты | `/cabinet` → «Мои отклики» |
| Общая биржа с поиском и фильтром по статусу | `/board` |
| Страница проекта: описание, автор, история статусов, форма отклика | `/project?id=1` |
| Статусы: «Ищу команду» / «В работе» / «Архив» + журнал изменений | страница проекта, `/admin` |
| Режим куратора: все проекты, смена любого статуса | `/admin` |
| Тёмная тема (запоминается), адаптив под 390px | кнопка ☾ в шапке |

## Как запустить (5 шагов)

Нужны **Python 3.10+** и **MySQL 8** или **MariaDB 10.6+**.

### 1. Создать базу

Сначала проверьте, что сервер БД вообще запущен:

```bash
sudo systemctl enable --now mariadb    # или: sudo systemctl enable --now mysql
```

Если сервиса нет (например, MariaDB поставлена вручную), поднимите её как обычный
пользовательский процесс:

```bash
mkdir -p ~/.local/share/campus-db/data
mariadb-install-db --no-defaults --datadir=~/.local/share/campus-db/data \
  --auth-root-authentication-method=normal --skip-test-db
mariadbd --no-defaults --datadir=~/.local/share/campus-db/data \
  --socket=~/.local/share/campus-db/mysql.sock --port=3306 --bind-address=127.0.0.1 &
```

Затем создайте схему:

```bash
mysql -u root -p < schema.sql
```

Скрипт создаст базу `campus`, четыре таблицы и двух пользователей для проверки.
Если этот шаг пропустить, сервер сам выполнит `schema.sql` при старте — но для отчёта
лучше показать отдельный запуск.

### 2. Установить зависимость

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Единственная библиотека — `mysql-connector-python`. Сервер написан на стандартном
`http.server`, поэтому Flask/Django ставить не нужно.

### 3. Указать параметры подключения

Скрипт по умолчанию подключается как `root` без пароля к `127.0.0.1:3306`.
Если у вас иначе — задайте переменные окружения:

```bash
export DB_HOST=127.0.0.1
export DB_PORT=3306
export DB_USER=root
export DB_PASSWORD=ваш_пароль
export DB_NAME=campus
```

Windows (PowerShell) - так же через env:

```powershell
$env:DB_PASSWORD="ваш_пароль"
$env:DB_PORT="3306"
python app.py
```

### 4. Запустить сервер

```bash
python app.py
```

В консоли появятся строки:

```
Биржа проектов — сервер запускается…
  БД и таблицы готовы
  Открыть в браузере: http://127.0.0.1:8000
```

### 5. Открыть в браузере

<http://127.0.0.1:8000>

Если 8000 занят: `PORT=8080 python app.py`.

## Как проверить за 2 минуты

1. Открыть `/register`, нажать «Создать аккаунт» с пустыми полями — под полями
   появятся сообщения, запрос на сервер не уходит.
2. Заполнить форму (пароль от 6 символов) — попадаете в кабинет.
3. В кабинете опубликовать проект — он сразу появится во вкладке «Мои проекты»
   и на общей бирже `/board`.
4. Выйти, войти под `timosh`, открыть чужой проект, отправить отклик.
5. Войти под `curator` (`/login`) → пункт «Куратор» → сменить статус проекта
   в таблице. На странице проекта появится запись в «Истории статусов».

## База данных

```sql
users        id, login, password, name, email, role, created_at
projects     id, owner_id → users.id, title, short_desc, body, tags, status, created_at
applications id, project_id → projects.id, user_id → users.id, message, created_at
status_log   id, project_id → projects.id, old_status, new_status, changed_at
```

- `users.login` и `users.email` — уникальные, повторная регистрация вернёт 409.
- Пара `(project_id, user_id)` в `applications` уникальна: откликнуться дважды нельзя.
- `ON DELETE CASCADE` — при удалении пользователя уходят его проекты и отклики.
- `status_log` хранит историю смены статусов, которую видно на странице проекта.

**Пароли.** В `users.password` лежит строка `pbkdf2_sha256$<итерации>$<соль>$<хеш>`.
Проверка - `hmac.compare_digest` (без утечек по времени). Открытого пароля в базе нет.

## API

Все ответы — JSON. Ошибки приходят с HTTP-кодом и полем `error`.

| Метод | Адрес | Что делает | Доступ |
|---|---|---|---|
| POST | `/api/register` | регистрация + вход | все |
| POST | `/api/login` | вход | все |
| POST | `/api/logout` | выход | все |
| GET | `/api/me` | текущий пользователь и счётчики | все |
| GET | `/api/projects?status=&q=&mine=1` | список проектов | все |
| POST | `/api/projects` | создать проект | вход |
| GET | `/api/projects/<id>` | проект + история статусов | все |
| PATCH | `/api/projects/<id>/status` | сменить статус | автор или куратор |
| POST | `/api/projects/<id>/apply` | откликнуться | вход, не свой проект |
| GET | `/api/applications` | заявки на мои проекты | вход |
| GET | `/api/applications/sent` | мои отклики | вход |

## Проверки на стороне JavaScript

- Пустые поля не уходят на сервер: сообщение под полем и общий блок над формой.
- Логин 3–20 символов (латиница, цифры, `_`, `.`), e-mail по шаблону.
- Пароль минимум 6 символов + счётчик символов под полем.
- Пароль и подтверждение должны совпадать.
- Кнопка блокируется на время отправки, чтобы не было двойного клика.
- Показ/скрытие пароля, счётчики символов у заголовка и описания проекта.

Те же правила повторяются в `app.py`: браузерные проверки легко обойти, поэтому сервер
всё валидирует заново и отвечает кодами 401 / 403 / 409 / 422.

## Творческая часть (сделано 7 из 7)

1. **Свой дизайн** — бумажный фон, тонкие линии, один акцент (индиго) и охра для
   «в работе»; без градиентов и больших скруглений. Логотип — точка в круге на CSS.
2. **Статусы** — «Ищу команду», «В работе», «Архив» с цветными метками и журналом
   изменений (`status_log`).
3. **Админ-режим** — роль `curator`, страница `/admin` со всеми проектами и сменой
   любого статуса. Обычному студенту сервер отвечает 403.
4. **Анимация** — карточки плавно появляются по очереди, блоки сообщений выезжают
   сверху. Уважается настройка `prefers-reduced-motion`.
5. **Поиск** — по всей бирже и по своим проектам, с задержкой 300 мс, чтобы не
   отправлять запрос на каждую букву. Плюс фильтр по статусу.
6. **Аватар с инициалами** в шапке и на карточках, например «ТК» у Тимофея Ковалёва.
7. **Тёмная тема** — переключатель ☾, выбор запоминается в `localStorage`,
   по умолчанию берётся системная настройка.

Дополнительно: адаптив под телефон 390px (навигация переносится вниз, таблицы
превращаются в карточки).

## Возможные проблемы

| Что видно | Причина и решение |
|---|---|
| `ОШИБКА: (2002) Can't connect to server on '127.0.0.1' (115)` / `Не удалось подключиться к MySQL` | **сервер БД не запущен** — включите сервис: `sudo systemctl enable --now mariadb` (или `mysql`) |
| `(1045) Access denied for user 'root'@'localhost'` | нужен пароль или другой пользователь: `DB_USER` / `DB_PASSWORD` |
| `(1049) Unknown database 'campus'` | база не создана: `mysql -u root -p < schema.sql` (или сервер создаст её сам при старте) |
| `(2003) Can't connect ... (111)` | MySQL слушает другой порт — проверьте `DB_PORT` (например, 3307) |
| `База данных недоступна. Проверьте настройки подключения.` | сервер запущен, но соединение пропало — проверьте MySQL |
| `Логин или e-mail уже заняты` | такой пользователь уже есть, войдите через `/login` |
| Страница `/cabinet` перекидывает на `/login` | сессии нет; сессии живут в памяти, после перезапуска сервера нужен новый вход |
| Порт занят | `PORT=8080 python app.py` |
